# Smart Playlists

Smart Playlists are deterministic MuseVault previews over the user's current saved library. They are generated by a server-only PostgreSQL query layer and are never persisted in MuseVault. A successful, non-empty preview can be explicitly exported to a new Spotify playlist.

## Data and coverage

The candidate universe is the latest `user_saved_tracks` membership joined to Spotify track, album, and ordered credited-artist metadata. A completed authoritative full-sync baseline is required, and generation pauses while a full sync is running under the same per-user advisory transaction lock used by the dashboard and Rediscover.

Audio constraints use only cached `track_audio_features` rows where `provider = reccobeats` and `status = available`. Missing values are unknown: they are not zero and do not mean that a track failed a filter. Coverage is reported as current saved tracks with available ReccoBeats features divided by all current saved tracks. No enrichment is started automatically.

Tempo is entered and stored as BPM, with an accepted range of 0–300. Energy, valence, danceability, acousticness, and instrumentalness are entered as percentages from 0–100 and converted to the database's 0–1 representation at the server boundary. All minimum and maximum bounds are inclusive and multiple filters use AND semantics.

## Definitions and validation

The five presets are:

- High Energy: energy ≥ 70%; energy descending, tempo descending, saved newest, track ID ascending.
- Danceable: danceability ≥ 70%; danceability descending, energy descending, saved newest, track ID ascending.
- Acoustic Leaning: acousticness ≥ 65%; acousticness descending, saved newest, track ID ascending.
- Instrumental: instrumentalness ≥ 50%; instrumentalness descending, saved newest, track ID ascending.
- Fast Pace: tempo ≥ 140 BPM; tempo descending, energy descending, saved newest, track ID ascending.

Every preset has a 30-track limit. The GET-based custom builder supports min/max bounds for all six features, the limits 20, 30, and 50, and bounded saved-date or audio-feature sorts. Track ID ascending is the final tie-breaker for every sort. Malformed numbers, duplicate recognized parameters, out-of-range values, unknown presets or sorts, unsupported limits, and a minimum greater than its maximum produce an explicit invalid-definition state. Unknown unrelated query parameters are ignored.

Filtering, ordering, match counting, and limiting happen in SQL. Preview results are bounded to at most 50 rows, artist names are aggregated in Spotify credit order, and duration is summed only across the returned preview.

## Boundaries and limitations

Normal page rendering and generation make no Spotify, ReccoBeats, MusicBrainz, Last.fm, recommendation API, or AI calls. Export availability is checked against the existing stored Spotify scopes in PostgreSQL. There is no randomization, paid provider, new API key, secret, environment variable, migration, playlist definition persistence, or usage tracking. The engine does not infer moods and does not mix Rediscover scores or listening/affinity weighting into ranking.

Current limitations are that previews depend on explicitly cached coverage and cannot be saved in MuseVault. Export creates a separate Spotify playlist with `public:false` after an explicit button press; it does not store a definition or export history, update an existing playlist, or schedule a refresh. In Spotify Web API terms, `public:false` prevents publication on the user's public profile and in search. It does not provide access control. MuseVault cannot set Spotify client-level private access; users can change access in Spotify itself.

## Explicit Spotify export

For a successful non-empty preview, the page provides a bounded playlist name and a **Create playlist on Spotify** action. Supporting copy explains that MuseVault creates it without publishing it publicly and that Spotify manages private access separately in its app. A preset defaults to `MuseVault — High Energy` or the corresponding preset name; a custom definition defaults to `MuseVault — Smart Playlist`.

Export requires the optional `playlist-modify-private` scope. The reconnect action uses the existing OAuth/PKCE flow and safely returns to the local Smart Playlist definition where possible. Missing export permission does not block previews or other read-only pages, and reauthorization preserves existing MuseVault data.

The authenticated export route validates the name and definition and regenerates the exact definition through the same database engine before contacting Spotify. It uses current saved membership and cached features at export time, preserving deterministic order and the 20, 30, or 50-track bound. If library or cache data changed after the displayed preview, the regenerated result can reflect those changes. Client-submitted track IDs are never an export source. No provider request or enrichment runs during this resolution.

Success shows the confirmed track count and a validated Spotify playlist link. If the playlist was created but adding items failed, a distinct partial-failure message explains that all preview tracks could not be confirmed and offers the created playlist for inspection. Ambiguous writes are not automatically replayed. See [Spotify playlist export](spotify-playlist-export.md) for the endpoints, security checks, and retry policy.
